### 1.4 수용 기준

- `npx vitest run --project server` PASS · `npx tsc --noEmit -p server` exit 0.
- 해시: 형식 정규식 · 같은 비밀번호 두 번 해시 → 다른 문자열 · 맞음 true / 틀림 false · 저장 문자열의 반복 수를 따른다(상수와 다른 값으로 만든 해시도 검증) · 깨진 문자열 false · 3자·33자 `VALIDATION_ERROR` · 이모지 4개 통과(코드 포인트 단위).
- 증명: 같은 입력 같은 값 · 해시가 다르면 다름 · 방이 다르면 다름 · 한 글자 변조 false · `null`·빈 문자열·129자 false.
- `enter` 7분기(02 §4.2 ①~⑦) 각 1건 이상. 주인·비밀번호 없음·안 잠긴 방은 `rate_limits` 행이 늘지 않는다. 6번째 비밀번호 시도 `RATE_LIMITED`(+`retryAfterSec`), 다음 분 창에서 회복, 초과 시 해시 함수 호출 0회(주입 감시).
- `setPassword`: 안 잠긴 방 → `locked: true` + 받은 증명이 `assertEntry` 통과 · 변경 → 옛 증명 `ROOM_LOCKED`, 새 증명 통과 · **같은 비밀번호로 재설정해도 옛 증명 무효** · `updated_at` 불변. `clearPassword` → `locked: false`, 멱등, 이후 재설정 시 해제 전 증명 무효.
- `createRoom` + 비밀번호: 행에 해시 1건 · `entryKey` 통과 · 비밀번호 위반이면 DB 호출 0회 · 비밀번호 없으면 `entryKey: null`·`locked: false`.
- `assertEntry`: 방·메시지 대상 각각 — 없음 통과 · 안 잠김 통과 · 주인 통과 · 증명 통과 · 그 밖 `ROOM_LOCKED`.
- `optionalToken`: 헤더 없음 · 잘못된 토큰 · 등급 미달 → principal 없음, 다음으로 진행(401·403 없음).
- 마이그레이션 0005 적용 뒤 기존 방 `locked: false`, 기존 rooms·messages·memory 테스트는 픽스처 `locked` 외 무수정 통과.
- 로그 grep: 비밀번호·해시·증명 값 0건. 이벤트 `room_password_set`·`room_password_cleared`·`room_enter_failed`·`room_enter_limited`에 `roomId`(·`mbId`)만.
- `PASSWORD_HASH_ITERATIONS` 결정 근거(측정 명령·결과 ms)를 rooms.md와 모듈 주석에 남긴다. **Free 요금제 기준 확정(02 U10)**: 해시 1회 CPU ≤ 5ms가 되는 값. 주석에 "Paid 확인 시 이 상수만 올린다 — 저장 문자열에 반복 수가 있어 옛 해시는 옛 값으로 검증, 마이그레이션 없음"을 적고, 반복 수가 다른 두 해시가 함께 검증되는 테스트 1건을 둔다.

### 1.5 하지 말 것

- 라우트·shared·ui 파일 수정 금지(contract 소유). 새 npm 패키지 금지(Web Crypto만).
- `env.ts` 밖에서 바인딩·`process.env` 읽기 금지. `TOKEN_SECRET`은 `services.ts`가 `config.tokenSecret` 값으로 파생 함수에 넘긴다.
- 프로세스 메모리 카운터·캐시로 시도 횟수를 세지 않는다(인스턴스마다 다르다 — D1 `rate_limits`만).
- 증명·해시를 D1 새 테이블에 저장하지 않는다(무상태).
- 비밀번호를 trim·정규화하지 않는다.
