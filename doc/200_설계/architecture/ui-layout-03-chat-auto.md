## 1. 중립 "…" 말풍선 (R-CHAT-014 🔒 · Q5)

### 1.1 가운데 열 4종 비교 (구분 규칙)

```
+----------------------------------------------+
|             어떠한 의지 · 16:42              |  유저 말풍선: 머리 줄(작성자·시각) + 배경 있는 상자
|           +---------------------+            |    배경 --bubble-user-bg, 최대 폭 86%
|           | 둘 다 뭐 하고 있어? |            |
|           +---------------------+            |
|         - [지시] 둘이 체스를 둔다 -          |  OOC: 한 줄 글자만. 상자·배경 없음
|                   +-----+                    |  중립 생성 중: 머리 줄 없음. 테두리 상자만,
|                   | ... |                    |    배경 없음, 점 색 --bubble-pending-fg
|                   +-----+                    |    role=status "응답을 만드는 중"(숨은 안내)
|          +------------------------+          |  중립 실패: 같은 자리·같은 상자.
|          | ! 생성에 실패했습니다. |          |    테두리 --bubble-error-border, role=alert
|          |        [재시도]        |          |    「재시도」 가운데, aria "응답 재시도"
|          +------------------------+          |
+----------------------------------------------+
```

구분 축은 세 가지다.

| 구분 | 유저 말풍선 | OOC 줄 | 중립 "…" (생성 중) | 중립 실패 |
|---|---|---|---|---|
| 머리 줄 | 「어떠한 의지」 · 시각 | 없음 | **없음**(이름·아바타·시각 없음) | 없음 |
| 상자 | 테두리 + 배경 `--bubble-user-bg` | 없음 | **테두리만, 배경 없음** | 테두리 `--bubble-error-border`, 배경 없음 |
| 글자 | 본문 `--font-serif` `--color-fg` | `--font-ui` `--text-sm` `--bubble-ooc-fg` | "…" `--bubble-pending-fg` | 문구 `--font-ui` `--text-sm`, "!" `--color-danger` |
| 폭 | 내용 폭, 최대 `--bubble-user-max-width`(86%) | 가로 전체 한 줄 | **내용 폭**("…" 한 줄) | 내용 폭, 최대 `--bubble-max-width`(78%, 좁은 화면 85%) |
| 높이(근삿값, 실측 우선) | 머리 줄 + 상자 | 한 줄 약 20px | **본문 1줄 상자 약 48px** | 문구 + 「재시도」 행 약 90px |
| 메뉴(롱프레스·우클릭) | 있음 | 있음 | 없음 | 없음 |

### 1.2 기존 PendingBubble 상자 재사용 판단

- **본문 상자는 그대로 쓴다.** `Bubble.module.css`의 `.body`(padding `--space-3` · 1px 테두리 · `--radius-lg`)에 `PendingBubble.module.css`의 `bodyBox`를 겹치는 현재 방식이 중립에도 맞는다. `failed .bodyBox` 테두리 규칙도 그대로 걸린다.
- **바깥 틀은 쓰지 않는다.** 캐릭터 틀(`character`·`sebastian`·`ciel`, 아바타 28px, 머리 줄 `head`)은 중립에서 렌더하지 않는다. 화자 배경색(`--bubble-*-bg`)이 붙으면 화자가 정해진 것처럼 보이기 때문이다.
- **가운데 정렬은 유저 말풍선과 같은 축을 쓴다.** 세로 쌓기 + 가운데 정렬(`.user`와 같은 축)이다. 다만 `.user` 클래스 자체는 쓰지 않는다. 쓰면 유저 배경색이 상자에 붙어 유저 말풍선과 구분이 사라진다.
- **실패 행의 「재시도」는 가운데 정렬이다.** 캐릭터 실패 말풍선은 왼쪽 정렬(`retryRow` flex-start)이고, 중립은 상자 전체가 가운데이므로 버튼도 가운데에 둔다.
- 결론: 상자·실패 테두리·숨은 안내·「재시도」 버튼은 재사용이고, 중립 전용으로 필요한 것은 "가운데 세로 틀"과 "배경 없음" 두 가지뿐이다. 클래스 이름·구현 방식(같은 컴포넌트의 `'auto'` 변형 · 인계패킷 §3 표)은 ui-designer가 정한다.

## 3. 유저 말풍선 작성자 줄 (R-CHAT-002 🔒 개정)

```
|             어떠한 의지 · 16:42              |   누가 썼든 같은 표기
|           +---------------------+            |
|           | 둘 다 뭐 하고 있어? |            |
|           +---------------------+            |
```

- 머리 줄 구조(작성자 · 시각, 가운데)는 그대로이고 글자만 「어떠한 의지」로 고정된다. 이전 표기 예("미샤 · 16:42")는 이 표기로 대체된다.
- 서버 응답 `authorName`이 비어 있어도 같은 표기를 쓴다(02 §6 `Bubble.test.tsx` 대체 이름 행).
- 폭 영향은 없다. 「어떠한 의지」는 한글 5자로 짧아 390px에서 머리 줄이 한 줄을 넘지 않는다.

## 7. 구조 제안 (미채택 · 요구 밖)

- **중립 "…" 아래 "누가 대답할지 고르는 중" 같은 보이는 문구.** 지금은 숨은 안내(role=status)만 있다. 화면 문구 추가는 요구 밖이라 제안만 한다.
- **선택이 끝난 순간 화자 쪽으로 미리 옮기기.** 응답이 끝날 때 한 번에 오므로(01 T2) 서버가 중간 신호를 보내야 한다. 계층을 넘는 변경이라 채택하지 않는다.

## 8. 크기 변화 메모

- **폭이 390px보다 넓을 때(모바일 가로).** 중립 상자는 내용 폭이라 가운데에 그대로 작게 남는다. 실패 상자는 최대 폭 78%(좁은 화면 85%) 안에서 문구가 한 줄로 펴진다.
- **높이가 줄 때.** 히스토리가 남는 공간을 차지하고 하단 바는 고정 높이라는 전제는 그대로다. 중립 실패(약 90px)가 캐릭터 실패(머리 줄 포함)보다 낮아 히스토리를 더 적게 먹는다.
