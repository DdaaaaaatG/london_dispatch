## 1. 현재 데이터 흐름

### 1.1 캐릭터 설정 → 프롬프트 (S3 구현 실물)

```
server/characters/{common,sebastian,ciel}.json      (저장소 파일, 빌드 시 번들에 포함)
   │ import (wrangler 번들러가 JSON 모듈로 묶음)
   ▼
server/src/llm/characters.ts
   parseCharacterFiles() — zod strictObject, 모듈 로드 시 1회
   · id ∈ {sebastian, ciel}, 파일 슬롯과 일치
   · name === shared CHARACTERS[id].name (표시명 단일 소스는 shared)
   · 실패 → CharacterFileError → Worker 시작 실패(=배포 거부)
   export CHARACTER_PROFILES · COMMON_PROMPT  (모듈 상수)
   ▼
server/src/llm/prompt.ts  buildSpeakPrompt(input, profiles = CHARACTER_PROFILES, common = COMMON_PROMPT)
   시스템 = world → [캐릭터 설정: name]+persona → [말투] → [캐릭터 규칙](있으면) → [출력 규칙] → [대화 기록 취급](GUARD_RULES, 코드 상수)
   사용자 턴 = <<대화 기록 시작>> 요약·히스토리 <<대화 기록 끝>> + "다음 발화자"
   ▼
server/src/messages/generate.ts   speak(103행)·regenerate(138행)가 기본 인자로 호출 (profiles 주입 안 함)
```

**확장 지점(좋은 소식).** `buildSpeakPrompt`는 이미 `profiles`·`common`을 인자로 받는다. generate.ts가 D1에서 읽은 값을 넘기기만 하면 prompt.ts의 호출 계약은 그대로다.

**현재 필드.** 캐릭터 `id, name, persona, speech, rules[]` · 공통 `world, outputRules[]`. 길이 상한 없음(min 1만). `outputRules` 문구는 R-LLM-003(🔒)이 내용("네 차례 … 1~3문장 … 이름표·마크다운 금지")을 고정하고, 후처리(R-LLM-004 이름표 제거)와 짝이다.

### 1.2 토큰 흐름 (주인 식별 관련)

```
갠홈 PHP(S5 handoff, 아직 없음)  mb_level >= LEVEL 이면 발급
  payload { mb_id, nick, ch_name, level(1~10), exp }  ── base64url(payload).base64url(HMAC)
  ▼ iframe src ?t=
ui/src/state/token.ts  메모리에만 보관(localStorage 금지, R-API-003)
ui/src/state/viewer.ts Viewer = { canWrite } — 토큰 유무로만. **payload를 해석하지 않는다**(토큰 값·이름을 viewer에 두지 않음)
  ▼ Authorization: Bearer
server/src/auth/middleware.ts requireToken → services.auth.authenticate
server/src/auth/token.ts verifyToken: 형식 → 서명 → payload(zod) → exp → level >= TOKEN_MIN_LEVEL
  → Principal { mbId, nick, chName, level, displayName }   ← mbId·level 모두 서명된 값
```

- 주인 판정에 쓸 수 있는 서명된 값은 이미 둘 있다: `mbId`, `level`. 토큰 형식을 바꾸지 않고 판정할 수 있다.
- 화면은 payload를 모른다. 주인 여부를 알려면 서버에 물어야 한다.

### 1.3 화면 분기

- `ui/src/App.tsx`는 외부 라우터 없이 `View = { screen: 'rooms' } | { screen: 'chat'; room }` 상태로 가른다. 3번째 화면은 유니온에 `{ screen: 'settings' }`를 더하는 방식이 기존 관례다.
- `viewer`는 App 상태 하나. 인증 실패(`TOKEN_REQUIRED·TOKEN_INVALID·LEVEL_TOO_LOW`)면 `revokeWrite`로 한 방향(읽기 전용) 전환한다.
- `ui/src/api/client.ts`의 `AUTH_FAILURE_CODES`에 **`LEVEL_TOO_LOW`가 들어 있다.** 주인이 아닌 경우를 `LEVEL_TOO_LOW`로 돌려주면 등급 통과 회원이 설정 판정 한 번에 읽기 전용으로 떨어진다(함정 T1).
- `RequestOptions.method`는 `'GET' | 'POST' | 'PATCH' | 'DELETE'`이다. `PUT`이 없다(S4 메모리 PUT 때도 필요한 추가).
- 공용 부품 `ui/src/components/ui/`: BottomSheet · Button · ConfirmDialog · IconButton · PromptSheet · StateView · TextArea · TextInput · Toast · Toggle · TopBar. 설정 화면에 필요한 부품은 탭 외에 다 있다.
- 레이아웃 카탈로그: L1(목록) · C1(대화) · S1(시트) · M1(긴 텍스트 편집, 전체 덮는 뷰). 설정 화면은 M1 변형이 맞다.

### 1.6 참고 원본 구조 (저장소 밖, 키 구조만 확인)

`업데이트.json` 최상위는 `{ DB, SETTINGS }`. **SETTINGS는 열지 않았다**(API 키 평문 포함 이력). `DB = { chats, worlds }`.

- `worlds[i]`: `id, name, description, aiRules[], lorebook[{title,content,keywords,enabled}], characters[]`
- `characters[j]`(30필드): `id, name, source_material, gender, age, race, height, weight, skin, body_type, three_sizes, hair_style, eyes, job, appearance_desc, accessories, personality_tags, voice, mental_state, sample_dialogue, entries[{title,content,keywords,enabled}], lorebook[]` + 성인용 8필드(`erogenous_zones, fetish, underwear, pubic_hair, perverted_features, dialogue_depth, sexual_psyche, sexual_behavior`). 모든 값은 문자열.
- E.No.S의 백업/복구: `Blob` + `URL.createObjectURL` + `a.download`로 내려받고, `<input type=file>` + `FileReader.readAsText`로 읽는다. **백업 파일에 SETTINGS(키)가 통째로 들어가는 것이 원본의 결함**이다. 이 프로젝트는 화이트리스트 직렬화로 막는다.

## 2. 문제점·제약

| # | 문제·제약 | 영향 | 설계 대응(02에서) |
|---|---|---|---|
| T1 | 주인 아님을 `LEVEL_TOO_LOW`로 주면 화면이 읽기 전용으로 떨어진다(`AUTH_FAILURE_CODES`) | ui 회귀 | 새 코드 `OWNER_ONLY`(403) |
| T2 | 화면은 토큰 payload를 해석하지 않는다(R-API-003 정신·viewer 설계) | 주인 판정을 화면이 직접 못 함 | 서버 응답(200/403)으로 판정 |
| T3 | 설정 텍스트가 시스템 프롬프트에 그대로 들어간다 | 프롬프트 주입 경로 | 주인만 쓰므로 수용·문서화, 꺾쇠 defang 적용 |
| T4 | 현 JSON은 모듈 로드 시 검증 = 배포 거부. D1 값은 요청 중에 읽는다 | 잘못된 값이 들어가면 speak가 깨질 수 있음 | 쓰기 때 검증 + 읽기 때 재검증, 실패 시 시드로 대체 |
| T5 | `outputRules`는 R-LLM-003 🔒 문구와 후처리(R-LLM-004)에 묶였다 | 주인이 바꾸면 이름표·장문 출력 | 편집 대상에서 제외(시드 고정) 권고 |
| T6 | 시스템 프롬프트가 길어지면 speak 1회 입력 토큰이 늘어 S3b 월 상한(10만원)에 영향 | 비용 | 필드별 상한 → 최대 약 1.2만 자 |
| T7 | iframe 안 파일 다운로드는 부모의 `sandbox` 속성에 달렸다(`allow-downloads`). 갠홈 테마 iframe 마크업(`rosebell-chatbot.php`)은 저장소 밖이라 확인 못 함. `head.php`에는 iframe 마크업이 없다 | 내보내기 실패 가능 | 복사용 텍스트 영역 대체 경로를 함께 둔다. **확인 필요** |
| T8 | 요청 중 D1 읽기 1회 추가(speak·regenerate) | 지연 수 ms | PK 1행 조회, 캐시 없음(즉시 반영 요구) |
| T9 | ui·shared에 zod 없음, 새 패키지 금지 | 화면 쪽 가져오기 검증 | shared에 순수 TS 사전 검사 + 서버 zod가 최종 |
| T10 | `request()`에 PUT 없음 | ui/api | 추가(api 폴더 내부 변경) |
| T11 | 토큰 만료(12h) 중 편집하면 저장이 `TOKEN_INVALID` → 읽기 전용 전환 | 편집 내용 유실 | 초안 유지 + 내보내기 허용 후 이탈 |
