## 1. 결정 1 — 주인 식별

| 안 | 방식 | 장점 | 단점 | 계약·handoff 영향 |
|---|---|---|---|---|
| A | `principal.level >= TOKEN_OWNER_LEVEL`(기본 10) | 설정 1개, 저쪽 등급만 맞추면 됨 | 그누보드 level 10은 부관리자에게도 줄 수 있다. 지인이 등급 체계를 **셋팅 중**(확정사항 §9 열린 항목 1)이라 의미가 흔들린다 | 없음 |
| **B (권고)** | `principal.mbId ∈ OWNER_MB_IDS`(쉼표·공백 구분 목록) | 지정한 회원만 정확히. 등급 체계 변경과 무관. `mbId`는 이미 서명된 값 | 주인을 바꾸려면 설정 변경 + 재배포(드묾) | 없음 |
| C | payload에 `owner: true` 추가 | 저쪽이 주인을 결정 | **토큰 형식 파괴 변경**(R-AUTH-001 🔒, 교차 벡터 V1~V8 재작성, PHP 조각·handoff 갱신, 저쪽 재적용) | 파괴 |

**권고 B.** 토큰 형식·PHP 조각·handoff가 그대로다. 판정은 `requireToken`(서명·만료·`TOKEN_MIN_LEVEL`) 통과 **뒤에** 한다.

- 설정 키 `OWNER_MB_IDS`. 비밀값은 아니지만 회원 ID를 공개 저장소에 남기지 않도록 **Secrets(`wrangler secret put OWNER_MB_IDS`) 권고**, 로컬은 `server/.dev.vars`. Workers는 vars와 secrets를 같은 `env`로 주므로 `env.ts` 파싱은 같다. `wrangler.toml [vars]`에 적어도 동작한다(사용자 선택 Q2).
- 빈 값·미설정 = 주인 없음 = 설정 엔드포인트 전부 403(닫힌 쪽 실패). 이때도 시드 기본값으로 speak는 계속 된다.
- 파싱: 공백·쉼표로 나눠 trim, 빈 조각 제거, 각 1~20자(그누보드 mb_id 길이), 최대 5개. 형식 위반은 기존 env 규칙대로 `CONFIG_INVALID`.

## 2. 결정 2 — 설정 필드 스키마

**방향: 현 필드를 유지하고 E.No.S의 캐릭터 관련 필드 일부를 더한다.** 신체 치수·성인용·로어북은 넣지 않는다.

### 2.1 `CharacterSettings` (API·D1·파일 공통 본체)

| 경로 | 화면 이름 | 형 | 필수 | 상한(코드 포인트) | 현 JSON | E.No.S 출처(가져오기) |
|---|---|---|---|---|---|---|
| `world` | 공통 세계관 | string | ○ | 2000 | `common.world` | `worlds[i].description` |
| `characters.{id}.sourceMaterial` | 원작·장르 | string | | 60 | (신규) | `source_material` |
| `characters.{id}.age` | 나이 | string | | 40 | (신규) | `age` |
| `characters.{id}.gender` | 성별 | string | | 20 | (신규) | `gender` |
| `characters.{id}.role` | 신분·직업 | string | | 80 | (신규) | `job` |
| `characters.{id}.persona` | 성격·배경 | string | ○ | 1500 | `persona` | (없음 — 현 값 유지) |
| `characters.{id}.personalityTags` | 성격 태그 | string | | 200 | (신규) | `personality_tags` |
| `characters.{id}.appearance` | 외형 | string | | 800 | (신규) | `appearance_desc`(+`hair_style`·`eyes`·`accessories`를 줄로 덧붙임) |
| `characters.{id}.relationships` | 관계 메모 | string | | 800 | (신규) | (없음) |
| `characters.{id}.speech` | 말투 | string | ○ | 800 | `speech` | `voice` |
| `characters.{id}.sampleDialogue` | 샘플 대사 | string[] ≤ 10 | | 항목당 200 | (신규) | `sample_dialogue`를 줄 단위로 나눔 |
| `characters.{id}.rules` | 규칙·금기 | string[] ≤ 20 | | 항목당 200 | `rules` | (없음) |

- `{id}`는 정확히 `sebastian`·`ciel` 두 키(strict). id·표시명은 본체에 없다. 표시명은 `shared/src/characters.ts`가 단일 소스이고 서버가 프롬프트에 넣는다(현 `name === CHARACTERS[id].name` 규칙의 귀결).
- 모든 문자열은 저장 전 `normalizeText`(앞뒤 trim), 길이는 `countCodePoints`(기존 limits 규칙). 배열 항목은 trim 후 빈 항목 제거.
- 필수(○)는 trim 후 1자 이상. 선택은 빈 문자열 허용(프롬프트에서 생략).
- 최대 시스템 프롬프트는 약 **1.23만 자**(세계관 2000 + 캐릭터 1명분 약 1.03만). speak 1회 입력 토큰이 늘지만 S3b `usage.ts`가 실측 토큰으로 누적하므로 별도 조치는 없다.
- `outputRules`는 본체에 없다. 시드 `common.json`에 그대로 두고 코드 상수처럼 쓴다(구조분석 T5, R-LLM-003 🔒 문구 보호). 열린 질문 Q3.

### 2.2 시드(기본값)로 강등

- `server/characters/{common,sebastian,ciel}.json`은 **파일 형식을 바꾸지 않는다**(id·name·persona·speech·rules / world·outputRules). `characters.ts`가 이를 읽어 `DEFAULT_CHARACTER_SETTINGS`(신규 필드는 `''`·`[]`)와 `OUTPUT_RULES`를 만든다. 모듈 로드 시 검증·배포 거부 규칙은 유지.
- D1에 행이 없으면 시드를 쓴다(`isDefault: true`). 파일을 고쳐 재배포하면 D1 행이 없는 동안만 반영된다. D1 행이 생기면 D1이 우선한다.
- 시드도 §2.1 상한을 넘지 않아야 한다(로드 시 같은 상한으로 검증).

### 2.3 프롬프트 매핑 (llm.md §7.1 확장 — R-LLM-003 개정)

시스템 섹션 순서. 빈 선택 필드는 그 줄·섹션을 통째로 생략한다.

```
{world}

[캐릭터 설정: {CHARACTERS[id].name}]
원작: {sourceMaterial} / 나이: {age} / 성별: {gender} / 신분: {role}   (비어 있지 않은 항목만 " / "로 잇는다. 넷 다 비면 줄 없음)
{persona}

[성격 태그]    {personalityTags}
[외형]         {appearance}
[관계]         {relationships}
[말투]         {speech}
[샘플 대사]    - … (말투 참고용 예시다. 그대로 되풀이하지 않는다)
[캐릭터 규칙]  - …
[출력 규칙]    - … (시드 고정)
[대화 기록 취급] - … (GUARD_RULES, 코드 상수)
```

- **호환 성질:** 신규 필드가 전부 비면 결과 문자열이 현행과 같다. 기존 스냅샷 테스트(SRV-T-167~171)는 그대로 통과해야 하고, 필드가 찬 경우의 스냅샷을 추가한다.
- 설정 텍스트에도 `defang`(`<<`·`>>` 치환)을 적용한다. 구분자 위조만 막고 내용은 손대지 않는다.
- 샘플 대사 섹션의 단서 문구는 코드 상수.

## 3. 결정 3 — 저장소

| 안 | 내용 | 판정 |
|---|---|---|
| **단일 문서 행(권고)** | `character_settings` 1행에 본체 JSON 전체 | 내보내기·가져오기·PUT이 모두 "전체 교체"라 원자적이다. 필드가 늘어도 마이그레이션 없음 |
| 캐릭터별 행 | 3행(common·sebastian·ciel) | 부분 갱신 이점이 없고 PUT이 3행 배치가 된다 |
| 필드별 컬럼 | 25컬럼 | 필드 추가마다 마이그레이션. 기각 |

```sql
-- 0003_character_settings.sql (초안 — 정본은 server-designer가 db.md §7.6에 확정)
CREATE TABLE IF NOT EXISTS character_settings (
  id          INTEGER PRIMARY KEY CHECK (id = 1),
  json        TEXT    NOT NULL CHECK (length(json) BETWEEN 2 AND 100000),
  version     INTEGER NOT NULL CHECK (version >= 1),
  updated_at  INTEGER NOT NULL,
  updated_by  TEXT    NOT NULL CHECK (length(updated_by) BETWEEN 1 AND 20)
);
```

- 쓰기: `INSERT … ON CONFLICT(id) DO UPDATE SET json = excluded.json, version = character_settings.version + 1, updated_at = excluded.updated_at, updated_by = excluded.updated_by RETURNING version, updated_at`. 동시 저장은 **마지막 쓰기 승리**(주인 1~2명, 드묾). 낙관적 잠금(`baseVersion` + 409)은 **선택(미채택)**.
- 읽기 비용: speak·regenerate마다 PK 1행 조회 1회. **격리체 캐시는 두지 않는다.** 격리체가 여러 개라 캐시는 "저장 즉시 반영"을 깨고, 조회는 이미 싸다(R-NFR-005 영향 없음).
- 읽기 때 zod로 재검증한다. 실패하면 `logger.error('character_settings_invalid', { field })`(본문 미기록) 후 **시드로 대체해 speak를 계속**한다(구조분석 T4). 쓰기 때 이미 검증하므로 수동 DB 조작에서만 생긴다.
- 읽는 시점: generate.ts가 잠금 획득 뒤 요약·히스토리를 읽을 때 함께 읽는다(LLM 호출 전).
- `updated_by`에는 `mbId`만 둔다(R-AUTH-006).
- 운영 적용: `/deploy`의 `wrangler d1 migrations apply --remote`가 0002·0003을 순서대로 적용한다. **코드 배포 전에 적용**해야 한다(테이블이 없으면 조회 실패). 롤백은 테이블을 남겨 둔 채 코드만 되돌리면 시드로 동작한다.

## 4. 결정 4 — 계약

### 4.1 엔드포인트 2개 추가

| # | 메서드·경로 | 미들웨어 | 요청 | 성공 |
|---|---|---|---|---|
| E15 | `GET /api/settings/characters` | requireToken → requireOwner | — | 200 `CharacterSettingsResponse` |
| E16 | `PUT /api/settings/characters` | requireToken → requireOwner → rateLimitWrites | `{ settings: CharacterSettings }` | 200 `CharacterSettingsResponse` |

```ts
type CharacterSettingsResponse = {
  settings: CharacterSettings
  /** 0 = 저장된 적 없음(시드). 저장할 때마다 1씩 증가 */
  version: number
  /** epoch ms. 시드면 null */
  updatedAt: number | null
  isDefault: boolean
}
```

- **GET도 토큰 필수(주인 전용 읽기).** R-AUTH-003 "읽기는 토큰 없이 허용"의 예외로 명시한다(§7 L6).
- PUT은 **전체 교체**다. 서버가 정규화한 값을 응답에 돌려주고, 화면은 그 응답으로 초안을 다시 맞춘다.
- 본문 상한 128KB. 넘으면 400 `VALIDATION_ERROR`. 경로 명명·zod 위치·`PATHS` 키 이름은 contract-designer가 확정한다.
- **내보내기·가져오기 엔드포인트는 없다.** 화면이 GET 응답으로 파일을 만들고, 파일을 읽어 초안에 넣은 뒤 PUT으로 저장한다.

### 4.2 에러

| 상황 | 코드 | status | 비고 |
|---|---|---|---|
| 토큰 없음 / 위조·만료 / 등급 미달 | `TOKEN_REQUIRED` / `TOKEN_INVALID` / `LEVEL_TOO_LOW` | 401 / 401 / 403 | 기존 그대로(화면은 읽기 전용 전환) |
| 유효 토큰이지만 주인 아님 | **`OWNER_ONLY`(신설, 15종째)** | 403 | 기본 문구 "캐릭터 설정은 갠홈 주인만 열 수 있습니다." 화면 `AUTH_FAILURE_CODES`에 **넣지 않는다**(구조분석 T1) |
| 본문 형식·필수·길이·개수·모르는 키 | `VALIDATION_ERROR` | 400 | message에 **첫 위반 한 건**을 한국어로. 예: "시엘 · 말투는 1~800자여야 합니다." 키는 `code`·`message` 둘(api.md §3.1 규칙 유지, `details` 키 신설 안 함) |
| 레이트리밋(PUT) | `RATE_LIMITED` | 429 | 기존 |
| D1 장애 | `INTERNAL` | 500 | 기존 |

`LEVEL_TOO_LOW` 재사용은 기각한다. 화면 공통 규칙에서 그 코드는 "쓰기 권한 상실"이라 읽기 전용으로 떨어진다. 주인 판정은 쓰기 권한과 별개다.

### 4.3 내보내기 파일 형식 (화면이 생성·해석)

```json
{
  "format": "london-dispatch/character-settings",
  "formatVersion": 1,
  "exportedAt": "2026-10-06T14:20:00.000Z",
  "settings": { "world": "…", "characters": { "sebastian": { "…": "…" }, "ciel": { "…": "…" } } }
}
```

- 파일명 `london-dispatch-characters-YYYYMMDD-HHmm.json`.
- **화이트리스트 직렬화.** 응답 객체를 펼치지 않고 §2.1 필드 목록(`shared/src/settings.ts`의 필드 상수)으로 새 객체를 만든다. `version`·`updatedBy`·토큰·설정 키는 넣지 않는다. 테스트로 출력 키 집합이 화이트리스트와 같음을 확인하고, `apiKey`·`API_KEY`·`SECRET`·`token` 문자열이 0건임을 확인한다.
- `formatVersion`이 모르는 값이면 가져오기를 거부한다.

### 4.4 가져오기 판별·매핑 (화면 순수 함수)

| 입력 모양 | 판별 | 처리 |
|---|---|---|
| 자체 형식 | `format === 'london-dispatch/character-settings'` | `settings`를 사전 검사 후 초안에 반영 |
| E.No.S 백업 | 최상위 `DB.worlds` 배열 | **`SETTINGS`·`DB.chats`는 읽지 않는다.** 캐릭터 `name`에 shortName(`세바스찬`/`시엘`)이 들어간 항목을 가진 world를 고른다(여럿이면 첫째). 매핑은 §2.1 표 마지막 열. 출처가 "없음"인 필드와 대응 캐릭터가 없는 쪽은 **현 초안 값 유지**. 성인용 8필드·신체 치수·entries·lorebook은 읽지 않는다 |
| E.No.S world 단독 | 최상위 `characters` 배열 + `description` | 위와 같은 매핑 |
| 그 밖 | — | "알 수 없는 파일 형식입니다." |

- 가져오기는 **초안만 바꾼다. 저장은 사용자가 「저장」을 눌러야** 한다. 되돌리기로 취소할 수 있다.
- 상한 초과 값은 잘라 넣지 않고 거부하며 어느 필드인지 알린다(열린 질문 Q5).
- 파일 크기 상한 5MB. E.No.S 전체 백업은 채팅을 포함해 클 수 있다. 넘으면 거부한다.

### 4.5 R-API-001·R-API-002 영향

엔드포인트는 14개에서 16개로, 에러 코드는 14종에서 15종으로 는다. 분류는 **추가**다. 기존 화면·저쪽 영향은 없고, 옛 화면 번들은 `OWNER_ONLY`를 api.md §3.4 규칙대로 `INTERNAL`로 정규화한다.

## 5. 결정 5 — 화면

### 5.1 주인 판정 (토큰 해석 금지와 충돌하지 않는 방법)

| 안 | 방법 | 장단 |
|---|---|---|
| **가(권고)** | 토큰이 있으면 App이 첫 렌더 뒤 1회 `getCharacterSettings()`를 부른다. 200이면 `isOwner = true`, 그 밖(403·401·NETWORK)은 `false` | 엔드포인트 추가 0. 등급 회원은 첫 로드마다 403 응답 1회(서버 로그 `owner_denied` info). 판정 실패는 ⚙ 미표시로 끝나고 토스트 없음 |
| 나 | `GET /api/me` → `{ owner: boolean }` 신설 | 의미가 깔끔하지만 엔드포인트가 하나 더 는다(17개) |
| 다 | 화면이 토큰 payload를 해석 | 토큰 해석 금지 규칙 위반. 기각 |

권고는 **가**다. 판정 결과는 App 상태 `isOwner`에 둔다. Viewer 타입은 바꾸지 않아 두 화면 영향을 줄인다. 판정 응답 본문은 버리고, 설정 화면은 열 때 다시 읽는다.

판정 응답이 401·`LEVEL_TOO_LOW`여도 **App은 읽기 전용으로 전환하지 않는다.** 판정은 조용한 탐침이고, 전환은 기존대로 실제 쓰기 실패가 결정한다.

### 5.2 진입·분기

- `View`에 `{ screen: 'settings' }`를 더한다. rooms 상단 바 오른쪽에 ⚙ IconButton(`aria-label="캐릭터 설정"`)을 둔다. **`isOwner`일 때만 렌더**한다(읽기 전용·등급 회원은 DOM 부재). chat에는 진입점이 없다.
- 설정 화면 ‹ 뒤로는 rooms로 간다. 미저장 변경이 있으면 ConfirmDialog("저장하지 않은 변경이 있습니다. 나갈까요?")를 띄운다.
- 마지막 본 방 기록(R-ROOMS-004)은 설정 화면과 무관하다.

- [⋯ 파일]은 BottomSheet(S1)를 연다. 항목은 「내보내기」·「가져오기」·「변경 되돌리기」(변경 있을 때만 활성).
- 「내보내기」 시트: 읽기 전용 TextArea(JSON 전문, 전체 선택 가능)와 「파일로 저장」 Button. iframe sandbox가 다운로드를 막아도 복사로 내보낼 수 있다(구조분석 T7).
- 「가져오기」 시트: 「파일 선택」(`<input type=file accept=".json,application/json">`), 붙여넣기 TextArea, 「불러오기」. 결과 요약("세바스찬·시엘·공통 반영, 무시한 항목 n개")을 토스트로 알린다.
- 내보내기 대상은 **마지막으로 읽거나 저장한 값**이다. 미저장 변경이 있으면 시트에 "저장하지 않은 변경은 포함되지 않습니다"를 표시한다(열린 질문 Q6).
- 로딩·오류(재시도)는 StateView. 403 `OWNER_ONLY`(주인 해제 후 재배포 등)면 안내 후 rooms로 가고 `isOwner = false`.
- 저장 중 인증 실패(401·`LEVEL_TOO_LOW`): `onAuthFailure`를 부르되 **초안은 화면에 남긴다.** 안내는 "인증이 만료되었습니다. 내보내기로 변경을 보관한 뒤 새로 고쳐 주세요." 이 상태에서 저장은 비활성이고, 내보내기는 초안 기준으로 허용한다(구조분석 T11).
- 390px, Rosebell 토큰, CSS Modules. 새 공용 부품 후보는 탭(Tabs) 1종이다. 설정 화면 전용으로 시작하고 승격은 후작업에서 판단한다.

### 5.4 상태 흐름


## 10. 저쪽(갠홈) 영향

- 토큰 형식·PHP 조각은 **변경 없음**(권고 B). 저쪽 재배포가 필요 없다.
- 확인 필요 1건: 갠홈 테마 iframe(`rosebell-chatbot.php`, 저장소 밖)에 `sandbox` 속성이 있는지. 있으면 `allow-downloads`가 있어야 「파일로 저장」이 된다. 없어도 복사 경로로 내보낼 수 있다. S5 `embed-guide.md`(R-HANDOFF-001)에 한 줄 추가 대상이다.
- 주인 `mb_id` 목록은 지인(또는 사용자)이 알려 줘야 한다. Secrets 입력은 S5 셋팅 절차에 넣는다.
