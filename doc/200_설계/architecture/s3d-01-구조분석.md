## 1. 현재 흐름

### 1.1 작성자 이름 (요구 ①)

비유: 지금은 출입증에 적힌 이름을 말풍선 머리에 그대로 붙인다.

```
토큰 payload { mb_id, nick, ch_name, … }
 → auth/token.ts:70        displayName = chName ?? nick                (R-AUTH-004)
 → messages/service.ts:90  author_name = displayName (+ author_mb_id 저장)
 → db/messages.ts:42       toMessage: authorName = row.author_name     ← 모든 조회·쓰기 응답이 이 한 곳을 지난다
 → 응답 Message.authorName  (토큰 없는 공개 GET /messages 에도 실명이 실린다)
 → ui Bubble.tsx:89 · MessageMenuSheet.tsx:33   authorName ?? '이름 없음'
 → llm/prompt.ts:64        `[유저 {safeName(authorName)}]` · GUARD_RULES 3번째 줄 '[유저 이름] 줄은…'
```

- 사용자가 본 「세바스찬의 주인」은 토큰의 `ch_name` 값이다. 저장소 코드에는 이 문자열이 없다(설정 테스트 픽스처의 관계 문구 1건뿐).
- 이름이 나오는 곳은 **유저 대사 말풍선 · 말풍선 메뉴 머리 · 프롬프트 유저 줄** 셋이다. OOC(`— [지시] … —`, 프롬프트 `[지시]`)에는 이름이 없다.

### 1.2 전송과 생성 (요구 ②)

```
전송      Composer → useMessageWrites.useSend → appendUser(POST /user) → 201 → messagesAppended → writeFinished   (AI 0회)
캐릭터 버튼 useSpeak → speakStarted(pending{character, generating}) → speak(POST /speak {character}) → speakSucceeded | speakFailed(+「재시도」)

server speak (messages/generate.ts:102)
  isCharacterId → deps.llm()(CONFIG_INVALID) → ensureBudget()(LLM_BUDGET_EXCEEDED)
  → withSpeakLock(speaking_until 90초){ Promise.all(기록 40 ∥ 요약 ∥ 설정) → buildSpeakPrompt(캐릭터 1명)
       → llm.complete(1~2회, LLM_BUDGET_MS 66초, 호출마다 usage 누적) → postprocessLine → insert } → 해제
```

- 화면 상태 `ui/src/state/chat.ts`: `writing`(쓰기 1건 팻말) · `pending`(`character: CharacterId`인 임시·실패 말풍선).
- 어댑터는 `generate({ system, turns, timeoutMs }) → { text, usage? }`(R-LLM-001 🔒). JSON 응답 모드·`generationConfig`가 없다.

## 2. 문제점·제약

| # | 문제·제약 | 대응(02) |
|---|---|---|
| T1 | 공개 읽기 API가 실명을 낸다. 화면만 바꾸면 실명이 응답에 남는다 | 서버 `toMessage` 한 곳에서 투영 |
| T2 | 응답은 끝날 때 한 번에 온다. 생성 시작 시점에 화자를 모른다 | 화자 미정 중립 임시 말풍선 |
| T3 | `useSend`는 성공 뒤 `writeFinished`로 팻말을 내린다. 이어서 speak를 따로 시작하면 사이에 캐릭터 버튼이 끼어든다 | 원자 전이 1개 |
| T4 | 저장과 생성이 다른 요청이면 생성만 실패할 수 있다 | 실패 말풍선 + 「재시도」(자동 선택 재실행) |
| T5 | R-NFR-001 70초 안에 화자 선택 호출이 더 들어가야 한다 | LLM 단계 66초를 나눠 쓴다 |
| T6 | 전송마다 AI 호출. 레이트리밋은 전송 1회에 2회 소모 | 기존 상한 그대로, 수치 안내 |
| T7 | 시드 `outputRules`(편집 불가, R-SET-006)는 "네 캐릭터" 1인 전제 | 2단계면 그대로 쓴다 |
| T8 | 테스트 다수가 "전송 = appendUser만"을 단언한다 | 02 §6 |
