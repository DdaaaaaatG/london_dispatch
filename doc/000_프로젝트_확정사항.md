# 런던_디스패치 프로젝트 확정사항 (단일 소스)

> 이 문서가 제품 규격·스택·계층·폴더·에이전트 구성의 **단일 기준**이다. `CLAUDE.md`와 `.claude/**`는 이 문서를 요약·참조한다. 어긋나면 이 문서가 맞다.
> 🔒 = 사용자(발주자·지인)가 직접 지정한 항목. 바꾸려면 사용자 확인이 필요하다.
> 작성 2026-10-05.

---

## 1. 제품 정의

- **런던_디스패치(London Dispatch)**: 흑집사 자캐 커뮤니티 갠홈 `http://london-gossip.my/`(아보카도 에디션)에 **iframe으로 끼워 넣는 AI 캐릭터 대화창**. 🔒
- 두 캐릭터 **세바스찬 미카엘리스 · 시엘 팬텀하이브**가 등장한다. 🔒
- 동작 🔒:
  - 「세바스찬」 버튼 → 지금까지의 방 대화를 보고 세바스찬이 한 턴 말한다.
  - 「시엘」 버튼 → 같은 방식으로 시엘이 한 턴 말한다.
  - 직전 발화가 누구든 상관없다(시엘이 두 번 연속 말할 수도 있다).
  - 입력창 → 유저가 지시(OOC)하거나 참여자로 말한다. **AI를 부르지 않고 저장만** 한다.
  - 메신저형 히스토리, 방(에피소드) 여러 개, 메시지 수정·재작성·삭제, 방 단위 장기기억(요약).
- 권한 🔒: **보기는 누구나**, **누르기(생성·수정·방 관리)는 갠홈 회원 중 일정 등급 이상만**. 로그인·등급은 갠홈(그누보드)이 관리하고, 우리는 갠홈이 발급한 서명 토큰으로 확인한다.
- 메인 화면 캐릭터 옆 대사창(말풍선) **연동 안 함**. 🔒
- 저쪽(갠홈 담당)은 **아보카도 본체 구조를 바꾸는 수정은 하지 않는다**. 테마 파일 안의 소폭 수정(주소 입력·토큰 몇 줄)만 한다. 🔒

## 2. 기술 스택

| 항목 | 값 |
|---|---|
| 런타임 | Node 22 LTS + TypeScript 5 (strict) |
| 모노레포 | npm workspaces — `server/` · `ui/` · `shared/` |
| 서버 | Fastify 5 (+ `@fastify/cors`, `@fastify/helmet`, `@fastify/rate-limit`, `@fastify/static`) |
| DB | SQLite (`better-sqlite3`), 파일 `data/london_dispatch.sqlite`. Railway Volume `/app/data` |
| 화면 | Vite 6 + React 18 + TypeScript. CSS Modules + CSS 변수 토큰(프레임워크 없음) |
| AI | 제공사 미정(Claude / OpenAI / Gemini 중 1). `server/src/llm/` 어댑터 뒤에 격리. 키는 서버 환경변수만 |
| 테스트 | vitest(서버·화면 공통) + `@testing-library/react` + supertest(API) |
| 린트 | eslint + prettier |
| 배포 | Railway(Nixpacks, `npm start`). https 도메인 필수(저쪽 PHP가 https만 받음) |
| Git | GitHub 단일 저장소, `main`, 1인 개발 |
| 화면 확인 | 브라우저 MCP(puppeteer)가 있으면 사용, 없으면 PowerShell 전체화면 캡처 |

- 새 의존성은 **사용자 승인 후 메인 세션에서만** 설치한다(설치 허가제). 초기 의존성 목록은 구축 승인 ②에서 한 번에 승인받는다.

## 3. 계층 위상과 경계 (🔒 3계층)

```
ui (iframe 화면)  →  contract (API 계약 · shared 타입 · 토큰 형식)  →  server (AI·저장·검증)
                                      ↑
                        갠홈 PHP(저쪽)도 contract의 당사자 — 토큰 형식·임베드 주소
```

| 계층 | 책임 | 소유 경로 |
|---|---|---|
| **server** | AI 호출·프롬프트 조립, 토큰 검증, 방·메시지·장기기억 저장, 레이트리밋, 환경변수 | `server/src/{env.ts,db,auth,rooms,messages,memory,llm}/`, `server/test/` |
| **contract** | 서버↔화면↔갠홈이 주고받는 **약속**: 엔드포인트, 요청/응답 JSON, 에러 코드, 토큰 형식, 임베드 규약 | `doc/200_설계/contract/api.md`(단일 소스) ↔ `shared/src/**` ↔ `server/src/routes/**` ↔ `ui/src/api/**` ↔ `doc/handoff/**` |
| **ui** | 패널 안 화면 전부: 방 목록, 대화, 버튼, 입력창, 수정·재작성 메뉴, 토큰 유무 분기 | `ui/src/{rooms,chat,components,state}/`, `ui/src/main.tsx` |

- **단방향.** ui는 `ui/src/api/` 래퍼만 호출한다. 화면 코드에서 `fetch`를 직접 쓰지 않는다.
- `doc/200_설계/contract/api.md`가 `shared/src/types.ts`·`server/src/routes/*`·`ui/src/api/*`·`doc/handoff/*`의 단일 소스다. 넷이 어긋나면 contract 결함이다.
- server는 ui를 모른다. 라우트(`server/src/routes/`)는 contract 소유이며 **얇게**(검증 → 서비스 호출 → 응답) 둔다. 라우트 핸들러 30줄 초과 = 로직이 server 서비스로 가야 할 신호.
- 비밀값(`process.env`)은 `server/src/env.ts`에서만 읽는다. 다른 파일의 `process.env`는 훅이 차단한다. 🔒
- 계층을 넘는 변경은 고치지 말고 **요구 명세를 만들어 사용자에게 보고**한다. 허락 후 해당 계층 매니저 세션으로 인계. 예외는 구축 모드의 task-manager.

## 5. 확정 규격

### 5.1 화면 (🔒 폭 390px 기준, 높이는 패널에 맞춤)

- 저쪽 패널: `rb-chatbot-panel` 390×640(모바일은 가로 꽉 참). 헤더 75px는 저쪽 것이므로 우리 화면은 **약 390×565** 안에서 그린다.
- **방 목록 화면**: 방 제목·날짜 목록, 「+ 새 방」(토큰 있을 때만).
- **대화 화면**: 상단(‹ 뒤로 · 방제 · 날짜 · ⋯ 메뉴) / 히스토리(말풍선, 위로 스크롤 시 과거 불러오기, 새 메시지 자동 스크롤) / 하단(캐릭터 버튼 2 + OOC 토글 + 입력창 + 전송).
- 토큰 없으면 하단 전체와 ⋯ 메뉴를 **그리지 않는다**(숨김이 아니라 미렌더).
- 말풍선 길게 누르기/우클릭 → 수정 · 재작성 · 삭제(토큰 있을 때만).
- 생성 중: "…" 임시 말풍선 + 버튼 잠금. 실패 시 임시 말풍선 자리에 오류 + 재시도.
- 마지막 본 방·스크롤 위치는 `localStorage`(try/catch, 없어도 동작).
- 시각: Rosebell 테마 계열(남색 반투명, Noto Serif KR). 토큰은 `ui_design_concept.md`.

### 5.2 API (요약 — 상세·타입·에러코드는 `doc/200_설계/contract/api.md`)

| 메서드·경로 | 토큰 | 역할 |
|---|---|---|
| `GET /embed` · `GET /embed?t=` | — | 화면(정적 파일) |
| `GET /api/rooms` | ✕ | 방 목록 |
| `POST /api/rooms` | ○ | 방 생성 |
| `PATCH /api/rooms/:id` · `DELETE` | ○ | 이름 변경 · 삭제 |
| `GET /api/rooms/:id/messages?before=&limit=` | ✕ | 히스토리(페이지) |
| `POST /api/rooms/:id/user` `{text, ooc}` | ○ | 유저 발화/지시 저장. AI 호출 없음 |
| `POST /api/rooms/:id/speak` `{character}` | ○ | 해당 캐릭터 1턴 생성 |
| `PATCH /api/messages/:id` · `DELETE` | ○ | 수정 · 삭제 |
| `POST /api/messages/:id/regenerate` | ○ | 같은 캐릭터로 재생성(그 이후 메시지가 없을 때만) |
| `GET /api/rooms/:id/memory` · `PUT` | ○ | 장기기억 보기 · 편집 |
| `GET /api/health` | ✕ | 상태 |

- 토큰은 `Authorization: Bearer <t>` 헤더. 화면은 `?t=`에서 읽어 메모리에만 둔다(localStorage 저장 금지).
- 에러 응답 `{ error: { code, message } }`. 코드는 `shared/src/errors.ts` 단일 소스.
- 쓰기 요청 레이트리밋: 토큰(mb_id) 단위 분당 N회(기본 20). `speak`는 방당 동시 1건.

### 5.3 토큰 (🔒 갠홈 등급 연동)

- 발급: 갠홈 테마 `theme/victorian/inc/rosebell-chatbot.php`에 저쪽이 붙이는 PHP 조각(우리가 작성, `doc/handoff/`). `$member['mb_level'] >= LEVEL`이면 발급.
- 형식: `base64url(payload).base64url(HMAC-SHA256(payload, SECRET))`. payload = `{ mb_id, nick, ch_name, level, exp }`(exp = 발급 + 12h, epoch 초).
- SECRET은 갠홈 PHP 조각과 서버 `.env`가 같은 값. 서버는 서명·exp·level 검사. 위조·만료 → `401 TOKEN_INVALID` / `403 LEVEL_TOO_LOW`.
- 토큰 없이 열린 화면 = 읽기 전용.
- LEVEL 숫자 **미정**(§9).

### 5.4 데이터 (SQLite)

```
rooms     id TEXT PK · title · created_at · updated_at
messages  id INTEGER PK · room_id · speaker('sebastian'|'ciel'|'user') · kind('line'|'ooc')
          · text · author_mb_id · author_name · created_at
memory    room_id PK · summary · source_until_id · updated_at
```

- 캐릭터 2명은 코드 상수(`server/src/llm/characters.ts`): id, 표시명, 프로필 이미지 경로, 성격·말투 프롬프트. 관리 화면 없음.
- 삭제는 실제 삭제(soft delete 없음). 방 삭제 시 메시지·memory 함께.

### 5.5 AI 생성 규칙 (`speak`)

1. 방의 `memory.summary` + 최근 메시지 N개(기본 40).
2. 시스템 프롬프트 = 세계관 공통 + **눌린 캐릭터**의 설정 + 출력 규칙("네 차례. 네 행동·대사만 1~3문장. 상대 대사·이름표·마크다운 금지").
3. 대화 기록은 `시엘: …` / `세바스찬: …` / `[지시] …` / `[유저] …` 형식으로 전달.
4. 결과를 후처리(이름표 제거·공백 정리)해 저장·반환.
5. 메시지가 요약 기준(기본 60개)을 넘으면 오래된 구간을 요약해 `memory`에 합친다(요청 뒤 백그라운드, 실패해도 응답은 성공).
6. 제공사 호출 타임아웃 60초, 재시도 1회.

## 8. 공통 규범 (모든 에이전트 본문에 반영)

- 문서·에이전트 본문은 **한국어**. 코드·키·식별자는 영문.
- **보고 채널은 하나**: 서브에이전트는 최종 응답 1회. SendMessage 중간 보고 금지.
- **실행 예산**: 위임문의 `예산: 도구 호출 N회 · 벽시계 M분`. 기본 구현 80/30, 설계 50/20, 검증·분석 30/10. 초과 시 `상태: 예산 초과 | 완료 | 미완료 | 막힌 지점 | 잔여 예상 | 권고`.
- **증거 기반 완료**: "될 것이다" 금지. vitest 결과·tsc exit code·스크린샷 경로·curl 응답으로 증명.
- **요구 범위 준수**: 요구ID로 역추적되지 않는 기능·필드·버튼·엔드포인트 추가 금지.
- **라이브러리 설치 허가제**: 새 의존성은 메인 세션에서 사용자 승인 후에만.
- **검증자 독립성**: checker·tester·reviewer·analyst에는 「적용 메모리」를 전달하지 않는다.
- **모드 판별**: 작업 수신 시 구축(build)/보강(maintain)을 먼저 판별한다.
- **비밀값 격리**: API 키·SECRET은 `.env`와 `server/src/env.ts`에만. 로그·응답·화면·문서에 실값 금지.
- kuro_keyviewer·안단테 고유 개념(Rust·Tauri·unsafe·후킹·오버레이·Django·GraphQL)은 **어디에도 남기지 않는다**.
