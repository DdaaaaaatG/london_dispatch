# SECRET·비밀값 전달 절차

> 실값 없음 · 작성 2026-10-07 · 소유 contract-designer · 요구 R-HANDOFF-003 · R-ENV-002 🔒 · R-SET-001 🔒 · R-NFR-004 🔒
> **이 문서·채팅·메일·스크린샷·커밋에 실제 SECRET·API 키·회원 아이디를 쓰지 않는다.** 이 문서의 `{{…}}`는 자리표시다.
> 2026-10-07 사용자 결정: 지인은 개발을 모른다. **SECRET은 우리가 만들고 넣는다.** 지인은 우리가 보낸 PHP 덩어리를 붙여 넣기만 한다.

> **지인용 요약**
> 1. 우리가 보낸 **한 번만 열리는 링크**를 연다. 안에 PHP 코드 한 덩어리가 있다.
> 2. 그 덩어리를 테마 파일에 붙여 넣는다(위치는 [token-snippet.php.md](token-snippet.php.md) 맨 위 요약).
> 3. 링크는 다시 열리지 않는다. 덩어리를 다른 곳(메모·채팅)에 따로 저장하지 않는다.

SECRET은 갠홈과 우리 서버가 함께 쓰는 **도장 비밀번호**다. 갠홈 PHP가 이 값으로 출입증(토큰)에 도장을 찍고, 서버는 같은 값으로 도장이 진짜인지 본다. 두 곳의 값이 **글자 하나까지 같아야** 한다. 이 값을 아는 사람은 아무 회원 이름으로나 글을 쓰고, 갠홈 주인 아이디로 캐릭터 설정까지 바꿀 수 있다. 그래서 따로 다룬다.

---

## 1. SECRET 규칙

| 규칙 | 이유 |
|---|---|
| **32자 이상**, 영문 대소문자와 숫자만(40자 이상 권장) | 서버는 32자 미만이면 모든 요청을 `500 CONFIG_INVALID`로 거절한다. 따옴표·공백·한글·특수문자는 PHP에 붙일 때 실수를 부른다 |
| **새로 만든 무작위 값** | 사람이 지은 문장·생일·사이트 이름은 안 된다 |
| 개발용 값(우리 PC의 `server/.dev.vars`)과 **다른 값** | 개발 값은 여러 사람·기계를 거친다. 운영 값은 운영 두 곳에만 둔다 |
| 테스트 값 `london-dispatch-test-secret-v1` 사용 금지 | 문서에 공개된 값이다(30자라 서버도 거부한다) |
| 운영 두 곳(Cloudflare·갠홈 PHP) 말고는 남기지 않는다 | 만든 메모·덩어리 파일·링크는 전달이 끝나면 지운다 |

## 2. 기본 방식 — 우리가 만들고 넣는다

| 순서 | 할 일 | 누가 |
|---|---|---|
| 1 | Cloudflare 계정 권한을 받는다([cloudflare-setup.md](cloudflare-setup.md) §1) | 지인 → 우리 |
| 2 | §3으로 SECRET을 만든다 | 우리 |
| 3 | Cloudflare Secrets `TOKEN_SECRET`에 넣는다(§4) | 우리 |
| 4 | [token-snippet.php.md](token-snippet.php.md) §2 전문에서 `{{SECRET}}` 자리만 실제 값으로 채운 **덩어리**를 만든다. LEVEL은 5 그대로 | 우리 |
| 5 | 덩어리를 **한 번만 열리는 비밀 링크**에 담아 지인에게 보낸다(아래 링크 규칙) | 우리 |
| 6 | 링크를 열어 덩어리를 테마 파일에 붙여 넣고 저장·업로드한다 | 지인 |
| 7 | 대조한다: 등급 5 이상 회원 계정으로 대화창을 열어 글쓰기 칸이 보이고 한 줄 써지는지 본다. 이상하면 그 페이지의 토큰을 `npm run token:test -w server -- verify`로 검사해 원인(서명·만료·등급)을 가른다(token-snippet §7) | 우리(필요하면 지인이 화면 확인) |
| 8 | 내 컴퓨터의 SECRET 메모·덩어리 파일·셸 명령 기록을 지운다 | 우리 |

**링크 규칙**

- 열람 **1회**, 만료 **24시간 이내**로 만든다(비밀번호 관리 앱의 "보내기" 기능 등).
- 링크 주소는 카카오톡 등으로 보내도 된다. **덩어리 내용 자체는 채팅·메일에 붙이지 않는다.**
- 메신저의 링크 미리보기가 링크를 먼저 열어 버릴 수 있다. 내용을 보려면 버튼을 한 번 더 눌러야 하는 방식을 쓴다.
- 지인이 "열리지 않는다"고 하면 새로 만든다. 누군가 먼저 열었을 수 있으면 **SECRET도 새로 만들어**(§6) 다시 보낸다.
- 덩어리 파일은 저장소(`doc/`·`server/` 등) 밖 임시 위치에서 만들고 링크를 만든 뒤 바로 지운다.

## 3. SECRET 만드는 법 (우리)

**가. Windows PowerShell**

```powershell
$b = New-Object byte[] 32; [Security.Cryptography.RandomNumberGenerator]::Create().GetBytes($b); [Convert]::ToBase64String($b) -replace '[+/=]', ''
```

- 영문·숫자 40자 남짓이 한 줄 나온다. 32자 이상인지 센다(모자라면 다시 실행).

**나. openssl** (Git Bash 등)

```bash
openssl rand -hex 32
```

- 0~9·a~f로 된 64자가 나온다.

- 아무 웹사이트의 "랜덤 문자열 생성기"는 쓰지 않는다. 만든 값이 남의 서버를 거친다.

## 4. 양쪽 입력 위치

| 쪽 | 위치 | 누가 |
|---|---|---|
| Cloudflare | 아래 명령. 값은 **물어볼 때 붙여 넣는다**(명령줄에 값을 치지 않는다) | 우리 |
| 갠홈 | `theme/victorian/inc/rosebell-chatbot.php`의 토큰 덩어리 안 `define('RB_CHATBOT_SECRET', '…');` 줄. 우리가 이미 채워서 보낸다 | 지인(붙여 넣기만) |

```bash
npx wrangler --config server/wrangler.toml secret put TOKEN_SECRET
```

- 화면으로 넣을 때는 Workers & Pages → `london-dispatch` → Settings → Variables and Secrets → Add → 종류 **Secret**. "Text"(평문)로 넣으면 다음 배포 때 지워지고 화면에도 보인다.

## 5. 함께 넣을 Secrets (모두 우리가 Cloudflare에)

| 이름 | 무엇 | 값의 출처 | 비우면 |
|---|---|---|---|
| `TOKEN_SECRET` | 위 도장 비밀번호 | 우리가 만든다(§3) | 모든 요청 `500 CONFIG_INVALID` |
| `LLM_API_KEY` | Google Gemini API 키 | 지인이 발급해 준 키 | 읽기는 되고 캐릭터 버튼만 실패 |
| `OWNER_MB_IDS` | 캐릭터 설정 화면을 열 수 있는 **지인(갠홈 주인) 회원 아이디 1개** | 사용자를 거쳐 전달받음(값은 문서에 쓰지 않는다) | 설정 화면은 아무도 못 연다(전원 `403 OWNER_ONLY`). 대화는 기본 설정으로 계속 된다 |

- 지인이 Cloudflare에서 할 일은 없다.
- `OWNER_MB_IDS` 값: **지인 회원 아이디 1개**(2026-10-07 사용자 결정). 닉네임이 아니라 **로그인 아이디**를 대소문자까지 그대로 넣는다(20자 이하). 서버 형식은 쉼표로 최대 5개까지 받지만 지금은 1개만 넣는다.
- 이 아이디는 이미 전달받았다. Secrets에 입력만 하고 문서·채팅에 다시 쓰지 않는다. 비밀번호는 아니지만 회원 아이디를 저장소에 남기지 않으려고 Secrets에 둔다.
- 이 세 개 말고 나머지 설정(등급·모델·한도 등)은 비밀이 아니어서 우리가 `server/wrangler.toml`에 적는다([cloudflare-setup.md](cloudflare-setup.md) §6).
- 그중 모델·단가(`LLM_MODEL`·`LLM_PRICE_*`)는 **기본값(폴백)**이다. 운영 중 캐릭터 설정 화면에서 Pro / Flash를 고를 수 있게 될 예정이다(설계 중). 어느 쪽이든 키는 `LLM_API_KEY` 하나를 쓴다.

## 6. 교체 절차 (SECRET을 바꿀 때)

언제: 값이 새어 나갔을 수 있을 때, 링크가 남에게 열렸을 수 있을 때, 값을 잃어버렸을 때(Cloudflare는 넣은 값을 다시 보여 주지 않는다).

| 순서 | 할 일 | 누가 |
|---|---|---|
| 1 | §3으로 새 값을 만든다 | 우리 |
| 2 | 새 덩어리를 만들어 비밀 링크로 보낸다(§2 링크 규칙) | 우리 |
| 3 | 지인이 링크를 열 수 있는 시간을 맞춘다 | 같이 |
| 4 | Cloudflare `TOKEN_SECRET`을 새 값으로 바꾼다 | 우리 |
| 5 | **곧바로** 테마 파일에서 「토큰 조각 시작」 줄부터 「토큰 조각 끝」 줄까지 지우고 새 덩어리를 붙여 넣어 올린다 | 지인 |
| 6 | 회원으로 대화창을 새로 열어 글이 써지는지 본다 | 우리 |
| 7 | 옛 값·새 값 메모와 덩어리 파일을 지운다 | 우리 |

- 4번과 5번 사이에는 모두 읽기 전용이 된다(글쓰기 실패). 몇 분 안에 끝낸다. 회원이 적은 시간대가 좋다.
- 서버 값을 바꾸는 순간 옛 값으로 찍은 토큰은 **바로** 무효다. 그 회원은 다음 글쓰기에서 읽기 전용으로 바뀌고, 페이지를 새로 고치면 새 토큰으로 돌아온다.
- 옛 값이 새어 나갔더라도 그 값으로 만든 가짜 토큰은 교체 즉시 막힌다. 정상 토큰은 원래 12시간이면 만료된다.
- `LLM_API_KEY`를 바꿀 때: 지인에게 Google에서 새 키 발급을 부탁 → 우리가 Cloudflare 값 교체 → 캐릭터 버튼 확인 → 지인이 Google에서 옛 키 삭제. 테마 파일은 그대로다.
- `OWNER_MB_IDS`를 바꿀 때: 우리가 Cloudflare 값만 바꾼다. 테마 파일은 그대로다.

## 7. 대안 — 지인이 직접 만들기 (기본 아님)

지인이 "SECRET을 아무에게도 넘기고 싶지 않다"고 할 때만 쓴다. 지인이 할 일이 늘어난다.

1. 지인이 §3 방법(또는 비밀번호 관리 앱 생성기, 길이 40·영문 대소문자·숫자만)으로 SECRET을 만든다.
2. 지인이 Cloudflare 화면(§4)에서 `TOKEN_SECRET`을 Secret 종류로 넣는다.
3. 지인이 token-snippet §2 전문의 `{{SECRET}}` 자리에 같은 값을 넣어 테마 파일에 붙인다.
4. 지인이 "넣었다"고만 알린다. 우리는 값을 모르므로 대조는 실제 화면으로만 한다.

---

## 8. 하지 말 것

- SECRET·API 키·덩어리 내용을 채팅·메일·문서·스크린샷·깃 커밋에 남기지 않는다.
- 갠홈 테마 파일을 통째로 남에게 보내지 않는다(SECRET이 들어 있다). 보여 줘야 하면 SECRET 줄을 `{{SECRET}}`로 바꾼 사본을 보낸다.
- 테스트 값·개발 값을 운영에 쓰지 않는다.
- Cloudflare에 "Text"(평문) 종류로 넣지 않는다.
