### 리뷰어별 확인 OK 요지

- **보안**: 미들웨어 순서와 토큰 검증 순서(서명 timingSafeEqual → exp → level, 서명 전 JSON 미해석)를 확인했다. 주인 비교는 정확 일치이고, env 파싱은 공백·쉼표·중복을 제거하며 최대 5개·1~20자다. 빈 목록이면 전원 403이다. 응답에 updated_by가 없고 로그에 본문이 없다. strictObject 3단, 11필드 필수, `__proto__` 거절을 확인했다. 400 문구에 입력값을 돌려주지 않고 500은 고정 문구다. SQL은 ?1~?3로 바인딩한다. 내보내기는 화이트리스트, 가져오기는 5MB 상한이고 초안에만 반영된다. 비주인 403 미카운트는 새 남용 경로가 아니다.
- **서버**: OWNER_MB_IDS는 env.ts에서만 읽고 의존 방향은 routes→services→db다. E15 requireToken→requireOwner, E16 +rateLimitWrites→bodyLimit→validate 순서는 api.md와 일치한다. speak·regenerate는 잠금 선점 뒤 설정을 1회 읽고 캐시가 없다. UPSERT 1문장이 version+1을 RETURNING으로 원자 처리한다. settings.get의 D1 throw는 500 INTERNAL로 가고, 시드 대체는 행 없음·parse 실패·재검증 실패에서만 한다. 에러 15종이 api.md와 일치하고 0003은 멱등이다.
- **코드**: Stage1에서 누락·과잉·계약 불일치가 없다. F-ST-01~21·F-RM-24~29가 전부 구현됐다. ⚙ 버튼은 canWrite && isOwner일 때만 렌더한다. fetch는 client.ts:104 한 곳뿐이다. 화면에 토큰 저장이 없다. R-SET-010 판정 실패 시 revokeWrite를 부르지 않는다(App.tsx:106-113). 최대 TSX는 175줄, 최장 함수는 약 47줄이다. 공용 컴포넌트 변경은 순수 추가다.
