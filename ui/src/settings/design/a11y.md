# settings 상세 설계 — 접근성 (분할 문서)

> 주 문서: `ui/src/settings/design.md`(RTM 포함). 이 파일은 주 문서 §9의 상세다.

## 1. 랜드마크·이름

| 요소 | 역할·이름 |
|---|---|
| 화면 루트 | `<main aria-label="캐릭터 설정">` |
| 제목 | TopBar `<h1 tabIndex={-1}>캐릭터 설정</h1>` — 마운트 시 포커스 |
| ‹ | IconButton `aria-label="뒤로"` |
| ⋯ | IconButton `aria-label="설정 파일 메뉴"` |
| 탭 | `role="tablist" aria-label="설정 묶음"`, 각 `role="tab" aria-selected aria-controls="settings-panel" id="settings-tab-{id}"`. `!`가 있으면 이름 = `세바스찬, 확인할 항목 있음` |
| 폼 영역 | `<section role="tabpanel" id="settings-panel" aria-labelledby="settings-tab-{activeTab}">` |
| 입력 | 공용 TextInput·TextArea `ariaLabel` = 필드 화면 이름(필수면 `성격·배경, 필수`). 목록 필드는 힌트 없이 `샘플 대사`·`규칙·금기`(보이는 라벨의 `(한 줄에 하나, 최대 n)`은 이름에 넣지 않는다, v1.2.1 확정). 상한 초과 시 공용이 `aria-invalid="true"` |
| ① 「가져오기」 비활성(stale) | 공용 SheetItem `isDisabled` → `<button disabled>`. 이름은 `가져오기` 그대로 |
| 로딩 · 오류 | StateView `role="status"` · `role="alert"` |
| 하단 줄 문구 | `<p role="status" aria-live="polite">` — 저장 중·저장됨·인증 만료 변화가 읽힌다 |
| 토스트 | 공용 Toast `role="alert"`(key로 다시 읽힘) |
| stale 안내 줄 | `role="alert"` |
| 시트 ①②③ | 공용 BottomSheet `role="dialog" aria-modal="true" aria-label={시트 제목}` |
| 시트 ④ | 공용 ConfirmDialog `role="alertdialog"` |
| ③ 오류 줄 | `<p role="alert">` |

## 2. 포커스 순서

1. 마운트: h1.
2. Tab 순서: ‹ → (h1은 tabIndex -1이라 건너뜀) → ⋯ → 선택된 탭 1개(로빙 tabindex) → 폼 필드(위에서 아래, 나이 → 성별) → 되돌리기 → 저장. 비활성 버튼은 건너뛴다.
3. 탭 선택(키보드): 포커스는 탭에 남는다. 폼으로는 Tab으로 들어간다.
4. 시트 열림: ① 첫 항목 「내보내기」 · ② 읽기 전용 TextArea · ③ 「파일 선택」 · ④ 「취소」(공용 ConfirmDialog 규칙). 시트 안 Tab은 처음↔끝 순환(공용 트랩).
5. 시트 닫힘(functions.md F-ST-12와 같은 서술): 1차는 공용 BottomSheet 복귀다. ①에서 ②·③으로 바꿀 때 같은 커밋에서 ① cleanup이 ⋯로 포커스를 돌린 뒤 ②·③ 마운트가 ⋯를 기억하므로, ②·③이 닫혀도 ⋯로 돌아간다. 2차(대체): `sheet`가 `'none'`이 된 커밋의 layout effect에서 `document.activeElement`가 `body`이면 ①②③은 ⋯(`fileMenuButtonRef`), ④는 ‹(`backButtonRef`)에 포커스한다. 두 ref는 IconButton `buttonRef`로 연결한다(components.md §1).
6. 저장 클릭 뒤(functions.md F-ST-10과 같다): 저장 중에는 「저장」이 비활성이라 포커스가 빠진다. 응답 뒤 성공 → h1 · 그 밖 실패(토스트) → 다시 활성이 된 「저장」(`saveButtonRef`) · stale(인증 실패) → h1, 안내는 F `role=alert`가 읽힌다 · `OWNER_ONLY` → rooms h1(7번).
7. 이탈 확인 「나가기」·OWNER_ONLY·열기 인증 실패: rooms가 새로 마운트되며 h1 포커스(rooms F-RM-05).

## 3. 키보드

| 키 | 위치 | 동작 |
|---|---|---|
| ← / → | 탭 | 이전·다음 탭 선택(순환) |
| Home / End | 탭 | 첫·끝 탭 |
| Enter · Space | 탭·버튼 | 선택·실행 |
| Enter | TextArea | 줄바꿈(전송 없음). TextInput에서는 무동작 |
| Esc | 시트 | 닫기(공용). ④는 취소와 같다 |
| Esc | 화면(시트 없음) | 동작 없음(뒤로가기로 쓰지 않는다 — 실수로 초안을 잃지 않게) |

## 4. 상태 알림

| 상태 | 알림 방법 |
|---|---|
| 로딩 | StateView `role=status` "설정을 불러오는 중" |
| 저장 중 | D `aria-live=polite` "저장 중..." · 버튼 비활성 |
| 저장 성공 | D 문구 변경 + 토스트 success(`role=alert`) |
| 저장 실패 | 토스트 `role=alert` |
| stale | F `role=alert` + D "인증 만료" |
| 필드 오류 | 상한 초과: 입력 `aria-invalid`. 필수 빈 칸·줄 수: 보이는 안내 줄 + 탭 이름 `, 확인할 항목 있음` + D 첫 위반 문구(live polite). 입력마다 alert를 내지 않는다 |
| 가져오기 거부 | ③ 오류 줄 `role=alert` |

## 5. 색·터치

- 상태 색은 글자와 함께 쓴다(`!` + 이름 접미사, D 문구, 안내 줄). 색만으로 전하지 않는다.
- 터치 영역: ‹·⋯ 44×44(공용), 탭 40 높이 × 약 120 폭(3등분), 하단 버튼 36 높이 × 64 이상 폭(구성안 §3·§11 미해결 2 — 36px 유지, chat 하단 1행 선례), 시트 항목·버튼 44.
- `prefers-reduced-motion`: 시트 모션은 공용 규칙.
